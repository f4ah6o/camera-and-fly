# 固定カメラによる機体位置推定の方式と精度を調査する

Status: open
Model: unknown
Created: 2026-09-08
Updated: 2026-09-08
Branch: codex/20260908-vision-localization-design

## 概要

単眼映像から StampFly の位置・向きを推定する方式を、固定カメラと識別マーカーの観測実験で選定する。

## 背景

現状は JPEG bytes の取得のみ。カメラは固定配置を暫定前提とし、機体搭載は前提にしない。ホストの STATUS は姿勢を度で返すが altitude/range の有効性情報は未整備。

## 問題

画像のピクセル誤差をそのまま roll/pitch へ比例変換すると、視点・yaw・高度の変化で符号やスケールが変わる。床面 homography だけでは飛行中の高さを正しく扱えない。

## 目標

校正・マーカー・姿勢/高さ推定の実装可能性と性能を実測し、採用方式に基づく推定器実装イシューを作る。

## 対象外

この課題での実飛行、PID 調整、一般物体の学習モデル、人物認識。

## 提案する方針

1. `docs/vision-design.md` にカメラ取付位置、視野、想定飛行領域、照明、機体上のマーカー位置/実寸/重量を記録する。条件が未確定なら机上コードと手持ち静止試験を先行する。
2. マーカー検出候補は AprilTag/ArUco 等の幾何学的方式から比較し、実装時点の公式 API・対応 Python/CPU を確認する。採用ライブラリ・version・依存インストールコマンドを決定する。マーカー ID と実寸は設定値とし複数候補を平均して誤追跡しない。
3. 内部パラメータ/歪み校正→camera-to-world 外部校正→機体 marker-to-body の変換を定義する。world は右手系メートル z-up、body 軸はファームウェアと照合し図示する。yaw の単位・符号を明示する。
4. known-size marker の pose と機体 ToF/高度情報の組合せを比較し、単眼 pose の曖昧解・斜視・遮蔽・反射を測る。高さが変わる領域で floor homography を流用しない。
5. prototype の出力案は `Observation(frame_id, received_monotonic, capture_monotonic_or_none, position_m, yaw_rad, quality, valid, reason)`。測定済み範囲外、再投影誤差過大、ID違い、古いframe、pose跳躍を invalid とする判定を選定する。
6. 機体または同寸マーカーを既知位置/高さ/向きに置き、推定誤差、欠損率、処理時間p95/p99を記録する。raw映像はローカル、共有用は合成 fixture とする。
7. 結果から校正ツール、推定器、品質gateの後続実装イシューを作る。具体的 API、fixture、誤差閾値、採用ライブラリとコマンドを記し、本課題の結論を参照する。

## 受け入れ条件

- [ ] 座標系・単位・取付変換が文書化され、左右/前後/上下の既知移動で符号が一致する。
- [ ] 最低3高さ×5平面位置と複数yawで誤差/欠損/遅延を測定する。
- [ ] 遮蔽と誤IDを無効観測として扱い、単眼推定の限界を明示する。
- [ ] 採否理由と確定した閾値を含む後続実装イシューがある。

## テスト計画

静止位置 fixture と合成投影に対する transform テスト。実カメラは手持ち/台上のマーカーで測り、プロペラを回さない。全位置の正解値の測り方と測定誤差も残す。

## リスク

単眼 pose の精度が必要な保持半径を満たさなければ、視野/マーカー寸法/追加カメラ等の再設計が必要。受信の新しさだけで実撮影時刻の鮮度を保証できない。
